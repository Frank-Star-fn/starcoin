# 双花防护与协议 v2

所有节点对收到的原始区块执行相同验证：创世块、高度、父块、时间戳、Merkle 根、哈希、PoW、交易签名、逐笔余额、nonce、重复交易和奖励规则。交易池规则只影响本地候选交易，不能替代区块共识验证。

金额支持十进制字符串或有限数字，最多八位小数；账本计算使用 BigInt 最小单位，拒绝负数、非有限数、超精度金额和溢出。交易手续费统一从 STC 扣除并燃烧。交易池只预留已确认可用资金，不把待确认收款视为可用余额。矿工每块只能创建第一笔、固定金额的 STC 奖励；cBTC/cETH 没有开放的 SYSTEM 铸币入口。

v2 交易 ID 是规范 JSON 数组中交易内容的 SHA-256。签名绑定版本、chainId、金额、币种、nonce、收发地址、备注和时间戳；公钥必须匹配发送地址。签名变化不改变交易 ID。同一地址的 nonce 从 0 连续递增，覆盖所有币种。普通交易不能携带特殊交易的 blockHeight。

v2 区块头绑定版本、chainId、共识参数摘要、目标、高度、父块、时间戳、Merkle 根和挖矿 nonce。难度目标使用整数有理数计算，在小数及整数边界保持单调。每块难度由该分支历史推导，累计工作量为各块 `floor(2^256 / (target + 1))` 之和，禁止使用节点声称的工作量或单纯链长度选链。工作量相同保持当前分支。

区块时间须大于前至多 11 块的时间中位数，且不能超过本地时钟允许的未来偏移。节点时钟应同步。旧格式历史保留原难度目标算法，但同样验证 PoW 和账本。

链切换前完整验证候选分支，重新验证交易池，并先原子保存临时文件再替换磁盘文件和内存状态。磁盘保存失败时不会清空交易池或提交新区块。重组回滚保留交易完整字段；与新主链冲突、已确认、余额不足的交易不再打包。回滚记录最多保留 1000 笔，重组事件最多保留 100 条。

## 确认与告警

`GET /api/transaction/:id/status` 返回 `pending`、`included`、`confirmed`、`reverted` 或 `unknown`。入块时确认数为 1，`PAYMENT_CONFIRMATIONS` 默认 6，表示收款策略达到阈值。被回滚但可重新打包的交易返回 pending 和 wasReverted=true。

`MINING_COINBASE_MATURITY=5` 表示奖励所在块之后还需五块，才成为可用余额。它与普通支付的确认阈值是独立规则。

`DEEP_REORG_THRESHOLD` 默认 6，达到阈值时记录错误日志和事件，链概览中提供告警。不依据某个节点自己的重组深度拒绝更高工作量的有效链，以免制造永久分叉。PoW 的确认是概率性的；这些修复不能保证多数算力攻击下的历史最终性。

## 旧链迁移

1. 停止所有矿工和节点，备份各节点原始链文件，选择同一份待审计历史。不要在不同高度独立选择检查点。
2. 使用旧网络一致的奖励、成熟期、初始难度和调整参数，运行 `node scripts/audit-chain.js data/blockchain_3000.json migration-report.json`。工具只读原链，报告首个不合法区块。重复交易、透支、伪造奖励、缺失签名、Merkle 篡改、PoW 不足均导致失败。
3. 审计失败时保留原文件并定位问题，不能跳过验证、自动改哈希、重签历史或把无效历史设为检查点。曾使用无授权代币空投的历史不满足本协议，需要另外设计明确的发行规则再迁移。
4. 审计成功后，在所有节点设置报告中的 CHAIN_ID、PROTOCOL_ACTIVATION_HEIGHT 和 LEGACY_CHECKPOINT_HASH，同时统一全部共识参数。激活高度为检查点高度加一，激活前一块的哈希必须固定。激活高度大于 1 时缺少检查点，或本地历史不匹配，节点拒绝启动。
5. 部署升级后的全部节点，再恢复挖矿。旧版签名只允许出现在固定检查点之前的历史中；激活后的新区块和入池交易必须使用 v2 与 nonce。旧待打包交易需由钱包重新构造签名。
6. 首次成功写入后保存格式为 4.0，记录共识摘要。启动时仍完整重放验证，不信任保存的余额、难度或工作量。无效文件保持原样并停止加载。

新网络默认从高度 1 激活 v2。共识参数变更会改变区块头摘要，必须协调协议升级，不能只改单个节点的 .env。支付确认阈值和重组告警阈值是本地收款策略，可独立调整。

客户端构造新交易应使用 `blockchain.createTransaction(from, to, amount, fee, note, currency, nonce)`，然后调用 `signTransaction(privateKey, publicKey)`。底层 Transaction 的默认构造格式保留给历史数据；新客户端也可显式传入第八个参数 `{ version: 2, chainId: 'starcoin-main-v2' }`。nonce 可以从 `/api/nonce/:address` 查询。

参考：[Bitcoin 区块共识与工作量](https://developer.bitcoin.org/devguide/block_chain.html)、[EIP-155 签名绑定链标识](https://eips.ethereum.org/EIPS/eip-155)。
