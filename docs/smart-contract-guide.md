# StarCoin 智能合约使用指南

本文介绍如何使用页面里的“EVM 智能合约”面板：连接钱包、准备 STC、部署合约、查询和修改合约数据、使用 ERC20，以及查看交易结果。第一次使用建议先完成 Counter 示例，再尝试 ERC20。

完整流程是：**连接 StarCoin → 存入 EVM STC → 挖矿确认 → 加载示例 → 估算并部署 → 挖矿并查询回执 → 调用合约。**

## 1. 先理解页面中的地址和余额

| 名称 | 格式与用途 |
| --- | --- |
| 原生钱包地址 | 不带 `0x` 的 32 位十六进制地址，用于原生 STC 转账、矿工奖励和取回资金 |
| EVM 钱包地址 | `0x` 加 40 位十六进制字符，用于 MetaMask、EVM STC 和 ERC20 收款 |
| 合约地址 | 格式与 EVM 钱包地址相同，但必须是已部署在 StarCoin 上的合约；填写在“合约地址”输入框 |
| 交易 ID / transactionHash | 用于查询回执，不是合约地址，不能填入“合约地址” |

同一钱包的原生 STC 和 EVM STC 分别记账。页面显示的 **EVM 余额**用于支付合约交易的 Gas 和随交易发送的 STC；ERC20 余额保存在合约内，不等于 EVM STC 余额。

原生 STC 支持 8 位小数，EVM STC 支持 18 位小数。ERC20 示例 SDT 也使用 18 位小数。

### 开始前先检查网络和合约地址

如果显示“当前钱包网络不是 StarCoin”，先点击“添加 / 切换 StarCoin”，在 MetaMask 中确认。页面会从当前 StarCoin 节点读取 EVM 余额，因此**看到 EVM STC 余额并不代表 MetaMask 已经切换到 StarCoin**。

如果下方出现 `invalid address ... value=""`，检查右侧“合约地址”是否为空。即使 `allowance` 的两个方法参数都填写了钱包地址，也仍然需要合约地址。

点击“ERC20 示例”只会加载 ABI、字节码和构造参数，不会自动部署。请按第 5 节部署并查询回执，或填写已经部署的 ERC20 合约地址。Gas 为 0 的旧资金存取回执不能证明 ERC20 已部署；部署回执需要包含 `contractAddress`。

## 2. 打开页面并选择签名钱包

如果节点已在运行，直接打开 <http://localhost:3000/>。否则在项目目录运行：

```powershell
cd C:\myfile\program\btc\starcoin
npm run start:node1
```

已有网络的首次升级步骤见 [README](../README.md#已有-evm-网络升级-metamask)。节点已完成升级时，无需重复准备网络配置。

### 使用 MetaMask

1. 解锁浏览器里的 MetaMask。
2. 在 EVM 面板点击“连接 MetaMask”，授权页面访问所选账户。连接成功后，“签名钱包”会切换为 MetaMask。
3. 点击“添加 / 切换 StarCoin”，在扩展中确认添加或切换网络。
4. 确认提示变为“已连接 StarCoin”，并核对页面显示的 MetaMask 地址。

也可以在 MetaMask 中手动添加：

| 字段 | 本机默认配置 |
| --- | --- |
| 网络名称 | `StarCoin` |
| 默认 RPC URL | `http://localhost:3000/rpc` |
| 链 ID | `155001` |
| 货币符号 | `STC` |
| 区块浏览器 URL | 留空 |

连接其他端口或机器时，替换 RPC URL 中的主机和端口。`localhost` 指运行 MetaMask 的那台设备；手机连接电脑节点时不能填写手机自己的 `localhost`。chainId 以节点配置为准。

MetaMask 模式的部署、写入和取回授权都在扩展里签名，页面不会要求 MetaMask 私钥或助记词。合约读取和 Gas 估算无需签名。

### 使用本地加密钱包

没有本地钱包时，在上方“我的钱包”点击“生成新钱包”或“创建 HD 钱包”，按页面提示完成备份；已有钱包可用“导入私钥”或“恢复 HD 备份”恢复。随后在“我的钱包”中选中要使用的地址。这一步也适用于只装了 MetaMask、还需要通过本地钱包挖矿和存入资金的新用户。

如果这个本地钱包只用于挖矿和向 MetaMask 存入资金，EVM 面板的“签名钱包”仍保持 MetaMask，无需改为本地签名。

将 EVM 面板的“签名钱包”设为“本地加密钱包”即可使用该钱包操作合约。后续步骤相同，写入由节点使用本地钱包的 PEM 私钥签名，不会弹出 MetaMask。

本地模式沿用项目现有的后端签名方式，提交和估算请求会把该本地钱包的私钥发送给所连接的节点。此模式适用于你信任的节点；MetaMask 模式由扩展保管密钥。

## 3. 准备 EVM STC

### 存入资金

1. 在页面上方选择一个有**可用原生 STC**的本地钱包。这个钱包负责支付存入金额。
2. 如果尚无 STC，通过“挖矿打包”获得奖励。默认矿工奖励有 5 个区块的成熟期，请以钱包的可用余额为准；总余额里未成熟的奖励暂时不能存入。
3. 在 EVM 面板的“STC 金额”填写要存入的金额，例如 `1`。
4. “存入的 EVM 地址”填写目标地址：MetaMask 模式可留空，默认使用已连接账户；本地模式留空时，使用所选本地钱包的 EVM 地址。
5. 点击“存入 EVM”。存入由上方选中的本地钱包签名，即使当前 EVM 签名模式是 MetaMask，也不会通过 MetaMask 扣款。提交成功后，页面会自动将本次交易 ID 填入“查看回执”。
6. 通过页面上方的“开始挖矿并打包交易”挖矿，或等待网络里其他节点挖矿；也可以开启“自动持续挖矿”。
7. 查询回执并刷新数据，确认目标账户的 EVM 余额增加。

只有签名或提交成功还不代表资金已经到账，必须入块。部署和后续写入都需要保留足够 EVM STC 支付 Gas。

### 三个容易混淆的金额输入

| 输入框 | 填写什么 |
| --- | --- |
| “STC 金额” | 存入或取回的 STC，例如 `1.5`，最多 8 位小数 |
| “随交易发送 STC” | 合约部署或方法调用时附带的 EVM STC，单位是 STC；不是 Gas 费用，也不是 SDT 数量 |
| ERC20 方法的数量参数 | 代币最小单位的整数，例如 1 SDT 填 `"1000000000000000000"` |

Counter 和 ERC20 示例的构造函数、写入方法都不接收附带 STC，使用这些示例时将“随交易发送 STC”保持为 `0`。

## 4. Counter：第一次部署与调用

Counter 是一个保存整数的合约，适合验证完整操作流程。

### 部署

1. 点击“Counter 示例”。页面会加载对应 ABI 和部署字节码。
2. “构造参数”保持 `[]`；“随交易发送 STC”保持 `0`。
3. 点击“估算部署 Gas”。成功后页面会自动填写带 20% 余量的 Gas 上限。
4. 点击“部署合约”。MetaMask 模式下，在扩展里核对 StarCoin 网络并确认交易。
5. 交易提交后，页面会把交易 ID / hash 填入“查看回执”，提示等待打包。
6. 挖矿或等待其他节点打包，再点击“查询回执”。
7. 回执应显示“已确认，执行成功”，并包含 `contractAddress`；页面会自动将该地址填入右侧“合约地址”。保存这个地址，以后可以继续操作同一个合约。

建议把合约名称、StarCoin chainId、节点 RPC URL、合约地址、部署账户和对应 ABI/合约 JSON 一起记在自己的笔记中。Counter 可以重新加载内置 ABI；自定义合约需要保留其编译 JSON。

### 查询和写入

每次选择 ABI 方法后，页面会重置方法参数，需要重新填写。

| ABI 方法 | 方法参数（JSON 数组） | 操作及预期结果 |
| --- | --- | --- |
| `count()` | `[]` | 点击“查询方法”，新合约返回 `0` |
| `set(uint256)` | `["42"]` | 先“估算调用 Gas”，再“提交合约交易”；签名、挖矿后 count 变为 42 |
| `increment()` | `[]` | 提交并打包后，在原值上加 1；如果此前是 42，则变为 43 |
| `fail()` | `[]` | 这是故意失败的查询示例，会返回 `Counter: intentional revert` |

写入打包后，再切回 `count()`，点击“查询方法”核对结果。查询读取已确认状态，所以 `set` 仍在交易池里时，`count()` 可能还是旧值。

展开“回执与事件日志”，`set` 和 `increment` 的成功回执会包含 `ValueChanged`，记录调用账户和写入的值。

## 5. ERC20：部署自己的 SDT 代币

### 部署与发行

1. 点击“ERC20 示例”，加载 `DemoToken`。
2. 默认构造参数为：

   ```json
   ["1000000000000000000000000"]
   ```

   这表示发行 **100 万 SDT**：`1000000 × 10^18`。全部代币发给部署交易的签名账户，MetaMask 模式就是当前签名账户。本示例固定供应量，没有额外增发方法。

3. 如果要发行 1000 SDT，将构造参数改为 `["1000000000000000000000"]`。发行数量是 SDT 数量，不是需要存入同等数量的 STC；STC 只用于支付这次部署的 Gas。
4. “随交易发送 STC”保持 `0`，点击“估算部署 Gas”，再点击“部署合约”并确认。
5. 挖矿，查询回执，确认成功并记录自动填入的 ERC20 合约地址。

### 查询代币信息

以下 `0x<…>` 是占位符。实际使用时，必须替换为完整的 `0x` 加 40 位十六进制 EVM 地址，不能原样粘贴占位符。

| ABI 方法 | 方法参数 | 用途 |
| --- | --- | --- |
| `name()` | `[]` | 返回 `StarCoin Demo Token` |
| `symbol()` | `[]` | 返回 `SDT` |
| `decimals()` | `[]` | 返回 `18` |
| `totalSupply()` | `[]` | 返回发行总量的最小单位整数 |
| `balanceOf(address)` | `["0x<当前签名钱包地址>"]` | 查询该账户的 SDT 余额 |
| `allowance(address,address)` | `["0x<持币账户地址>","0x<被授权账户地址>"]` | 查询前者允许后者代为转出的额度 |

例如，默认发行后 `balanceOf` 返回 `1000000000000000000000000`，换算后是 100 万 SDT。`allowance` 不用于查余额；未执行授权时通常为 0。

### 转账 1 SDT

1. 确认当前签名账户持有 SDT，并且有 EVM STC 支付 Gas。
2. 选择 `transfer(address,uint256)`，填写：

   ```json
   ["0x<收款方的EVM地址>", "1000000000000000000"]
   ```

3. “随交易发送 STC”保持 `0`，估算 Gas，再提交合约交易。
4. 在 MetaMask 确认，挖矿并查询回执。成功回执包含 `Transfer` 事件。
5. 选择 `balanceOf(address)`，填写收款方地址，查询结果应增加 `1000000000000000000`，即 1 SDT。

收款方是 EVM 钱包地址，不能填写原生 32 位地址，也不能误填这个 ERC20 合约地址。

### 授权其他账户代为转账

`approve` 用于授权指定账户从你的余额中代为转出代币，普通 `transfer` 不需要先执行它。

例如账户 A 授权账户 B 最多使用 10 SDT：

```json
["0x<账户B的EVM地址>", "10000000000000000000"]
```

由 A 选择 `approve(address,uint256)`，提交并打包。随后通过 `allowance` 查询 `["0x<账户A的EVM地址>","0x<账户B的EVM地址>"]`，应得到 10 SDT 对应的整数额度。

如果 B 要将 A 的 1 SDT 转给 C，先连接并选择 B 作为签名账户，再选择 `transferFrom(address,address,uint256)`：

```json
["0x<账户A的EVM地址>", "0x<账户C的EVM地址>", "1000000000000000000"]
```

B 需要有自己的 EVM STC 支付 Gas；A 需要有代币余额和足够授权额度。提交、挖矿后额度按实际转出数量减少。A 可以再次执行 `approve`，把 B 的额度设为 `"0"` 来撤销剩余授权，也需要挖矿确认。

### 在 MetaMask 中显示 SDT

保持页面里的合约地址为 ERC20 地址，点击“导入 ERC20 到 MetaMask”，在扩展中确认添加代币。导入只影响钱包显示，不会发行或转移代币，不需要挖矿。

收款账户也可以在 MetaMask 的“导入代币”中填写同一合约地址。必须选中 StarCoin 网络；同名 SDT 或其他网络里的同一地址不代表本网络上的同一合约。

## 6. 操作已经部署的合约或导入自己的合约

### 继续使用已有合约

1. 加载匹配的示例或导入该合约的 JSON，得到 ABI。
2. 手动在“合约地址”填写之前保存的 StarCoin 合约地址。
3. 选择方法并填写参数，然后查询或提交写入。无需再次点击“部署合约”。

ABI 描述有哪些方法、参数类型和返回值。它必须与目标合约匹配。加载另一个示例不会自动替换已有合约地址，也不会改变链上的合约；从 Counter 切换到 ERC20 时，需要部署 ERC20 或填写已有 ERC20 地址。

### 导入自己的合约 JSON

点击“导入合约 JSON”选择文件。页面支持 `abi` 数组、`bytecode` 字符串或 `bytecode.object`，以及可选的 `constructorArgs` 数组；文件最大 1 MB。

```json
{
  "contractName": "YourContract",
  "abi": [],
  "bytecode": "0x...",
  "constructorArgs": []
}
```

上面仅展示文件结构，`abi` 和 `bytecode` 必须替换为真实编译结果。部署使用 creation bytecode，不能用已经部署的 runtime bytecode。只操作已有合约时可以只导入 ABI，再填写目标合约地址。

本网络固定使用 **Shanghai** 执行规则，自己的 Solidity 编译结果也应设置 `evmVersion: "shanghai"`。项目的示例源码位于 `contracts/Counter.sol` 和 `contracts/DemoToken.sol`；修改示例后，在项目目录执行：

```powershell
npm run contracts:build
```

命令使用固定的 solc 0.8.30，更新 `public/contracts/Counter.json` 和 `public/contracts/DemoToken.json`。重新加载页面示例即可使用新字节码；已经部署的合约不会随源码修改而更新。

## 7. Gas、回执与挖矿确认

### Gas 怎么填

Gas 上限是允许执行的计算量，不是 STC 金额。先点击对应的“估算部署 Gas”或“估算调用 Gas”，页面会填写带 20% 余量的上限。默认单笔最大 5000000 Gas，每块最大 30000000 Gas。

实际费用为 `gasUsed × effectiveGasPrice`，从签名账户的 EVM STC 余额扣除。Gas 上限未用完的部分不会全部扣费，但提交前需要有足够余额覆盖费用上限和附带 STC。当前 baseFee 会动态变化，所有 Gas 费用包括优先费都燃烧。

查询方法和 Gas 估算在状态副本上执行，不会扣链上余额，也不会修改合约。估算成功后，余额或状态变化仍可能导致实际交易失败。

估算失败时，先看面板底部的“操作失败”提示：检查 EVM STC 余额、参数格式和“随交易发送 STC”；方法调用再检查合约地址与 ABI 是否匹配，部署则检查构造参数与 Shanghai 字节码。修正后重新估算；合约主动拒绝执行时，单纯提高 Gas 不能解决问题。

### 回执怎么看

| 页面状态或字段 | 含义 |
| --- | --- |
| 待打包 | 交易已提交，尚未入块；需要挖矿或等待其他矿工 |
| 已确认，执行成功 | 已入块且执行成功；确认数表示从入块起已有多少个主链区块 |
| 执行失败，Gas 已扣除 | 已入块但执行 REVERT 或 out-of-gas；合约/value 状态回滚，Gas 仍扣除，EVM nonce 递增 |
| 未找到该交易 | ID/hash 不存在于当前节点可见的主链或交易池，可能输入错误、查错节点或发生了重组 |
| 已因分叉回滚 | StarCoin 回执表明原交易所在分支被替换，需要再次核对交易是否回池或重新入块 |
| `contractAddress` | 成功部署生成的合约地址；普通方法调用及资金存取没有部署地址 |
| `gasUsed`、`feeWei` | 实际 Gas 用量、以 wei 计的费用 |
| `logs` / `decodedLogs` | 合约产生的原始事件及按当前 ABI 解码的事件 |

StarCoin 采用 PoW。页面显示执行成功说明已经入块，但仍可能发生分叉；确认数越多，越便于评估交易稳定性。RPC 在重组后可能返回空回执，回滚交易经重新校验后可能再次进入交易池。

## 8. 将 EVM STC 取回原生钱包

1. “STC 金额”填写取回金额，例如 `0.5`，最多 8 位小数。
2. “取回的原生地址”填写不带 `0x` 的 32 位小写十六进制原生钱包地址。MetaMask 模式下必须有收款地址；选择本地钱包后，页面可自动填入。
3. 点击“取回原生账户”。MetaMask 模式下，扩展会展示 `Withdraw` 签名请求，绑定账户、收款地址、金额、授权 nonce 和期限。
4. 核对地址和金额后签名。金额字段 `AmountUnits` 使用原生最小单位：取回 0.5 STC 对应 `50000000`。提交成功后，页面会自动将本次取回交易 ID 填入“查看回执”。
5. 挖矿，查询回执并刷新余额。成功后 EVM STC 减少，指定原生账户的 STC 增加。

取回是 StarCoin 的签名授权交易，当前回执的 Gas 为 0；它不会自动卖出 ERC20。SDT 等代币仍留在合约中，只有 EVM STC 能通过这个入口取回。小于原生精度的 wei 零头留在 EVM。

## 9. 常见问题

| 现象 | 检查与处理 |
| --- | --- |
| `invalid address ... value=""` | “合约地址”为空。加载示例后先部署、挖矿、查部署回执；操作已有合约时填写其地址 |
| 当前钱包网络不是 StarCoin | 点击“添加 / 切换 StarCoin”。节点查询得到的 EVM 余额不能证明扩展网络已切换 |
| MetaMask 里没有 STC，原生钱包却有余额 | 两套余额分别记账；选择原生钱包，向 MetaMask EVM 地址存入 STC 并挖矿 |
| 存入提示原生余额不足 | 检查上方所选本地钱包的可用余额，未成熟矿工奖励不可支付 |
| `insufficient funds` / EVM 余额不足 | 签名账户需要 EVM STC 覆盖 Gas 和附带 STC；拥有 SDT 不能代替 STC 支付 Gas |
| `allowance` 为 0 | 尚未授权或额度已用完。查余额应选择 `balanceOf`，普通代币转账使用 `transfer` |
| ERC20 数量不对 | 方法参数用最小单位整数：1 SDT = `10^18`；大整数用带引号的字符串 |
| 合约调用失败或返回值无法解码 | 检查合约地址是否属于当前 StarCoin 网络，以及 ABI 是否匹配。切换示例不会自动切换合约地址 |
| ERC20 转账失败 | 检查签名账户的代币余额；`transferFrom` 还需要持币者对当前签名账户的授权额度 |
| `Counter: intentional revert` | 调用了专门演示失败的 `fail()`；这是示例的预期行为 |
| 提交后一直待打包 | 检查是否有节点挖矿、节点是否同步；仅确认 MetaMask 签名不会自动出块 |
| 用户拒绝签名 | 本次操作不会提交新的交易；可以重新发起并确认 |
| MetaMask 不显示 SDT | 切换到 StarCoin，导入实际部署的 ERC20 合约地址；刷新钱包并核对当前账户 |

本指南使用普通 EVM 账户和 Shanghai 合约。当前不支持 MetaMask 的 EIP-7702 高级账户功能、blob 交易，以及依赖未实现 RPC 的应用。
